# Silver Diamond Game Engine — документация

> Версия документа: 0.4 · Язык: C99 (Mingw / GCC / Clang)

Движок Silver Diamond — это собственный игровой движок студии Selenium ground:
окно, ввод, рендер (OpenGL 3.3+), загрузка glTF/GLB, текстуры (stb_image),
анимации, звук, 2D-интерфейс и физика. Всё это собрано в одну динамическую
библиотеку (`sdge.dll` / `libsdge.so`), а игры и утилиты линкуются только с
публичными заголовками из `API/include`.

В этой версии добавлены **редактор сцен**, **наложение текстур на отдельные
элементы модели** и **переработана физика** (см. раздел 6).

---

## 1. Быстрый старт

```bash
python build.py            # собрать движок и приложение из src/
python build.py run        # собрать и запустить
python build.py editor     # собрать редактор сцен -> build/<plat>/<var>/sdge_editor.exe
python build.py demo --demo texture_demo
python build.py test       # собрать и прогнать тесты физики (без окна)
python build.py sdk        # выгрузить публичные заголовки и библиотеки в API/
python build.py rebuild     # пересобрать всё с нуля
python build.py clean
```

Полезные ключи: `--debug` (‑O0 ‑g), `--nogl` (сборка без OpenGL),
`--name NAME` (имя бинарника), `--wsl` (сборка внутри WSL).

Требования: компилятор C99 (MinGW/GCC/Clang) и Python 3.8+. Библиотеки OpenGL
и X11 подтягиваются системой; на Windows нужен `opengl32.dll` (уже есть в
составе Windows), на Linux — `libGL.so`, `libX11.so` и, опционально,
`libasound.so` для звука.

## 2. Структура проекта

```
core/            исходники движка (собираются в sdge.dll)
  graphics/      окно, рендер, GPU-меши, шейдерный 2D-интерфейс
  math/          vec3/quat/mat4, фрустум (header-only)
  assets/        arena, файлы, glTF/GLB, изображения (stb_image), шрифты, mp3
  anim/          сэмплирование анимаций, палитры скинов
  audio/         микшер 48 кГц, waveOut / ALSA
  subjects/3D/   камера, модель, источники света
  subjects/2D/   камера и GUI (div, button, input, label, checkbox, ...)
  physics/       2D и 3D физика твёрдых тел
  scene/         менеджер сцен и переходы
  editor/        редактор сцен (иерархия, выбор, гизмо, экспорт glTF)
src/             приложения (main.c — хаб проектов, editor.c — редактор)
demos/           демонстрационные программы
include/         сторонние заголовки: glad, minimp3, stb_image.h
API/             выгружаемый C SDK (заголовки + libsdge.a + sdge.dll)
tools/           вспомогательные скрипты на Python
```

Списки исходников лежат в Python-конфигах: `core/config.py` — файлы движка,
`src/config.py` — файлы приложения. Чтобы добавить модуль, допишите его в
`core/config.py` и в `build.py` в список `sdk_headers` (если модуль должен
попасть в публичный SDK).

## 4. Текстуры и stb_image

Движок использует **stb_image** (`include/stb_image.h`, реализация собрана в
`core/assets/texture.c`). Файл `stb_image.h` лежит в `include/` и подключается
через `-I include`, который уже есть в `build.py`.

Декодирование картинки с диска:

```c
#include <sdge.h>

sdga_image img;
if (sdga_image_load_rgba("assets/textures/wood.png", &img) == 0) {
    /* img.pixels - RGBA8, img.w * img.h * 4 байт, верхняя строка первая */
    unsigned tex = sdgr_upload_texture(img.w, img.h, img.pixels);
    sdga_image_free(&img);
}
```

Декодирование из памяти (так читаются картинки внутри GLB и data-URI):

```c
sdga_image img;
sdga_image_load_rgba_mem(data, size, &img);
```

Загрузка в GPU с полным описанием (sRGB, фильтры, повтор, мип-карты):

```c
sdgr_texture_desc desc = {0};
desc.srgb        = 1;                       /* цветовая карта -> GL_SRGB8_ALPHA8 */
desc.wrap_s      = SDGR_REPEAT;
desc.wrap_t      = SDGR_REPEAT;
desc.min_filter  = SDGR_LINEAR_MIPMAP_LINEAR;
desc.mag_filter  = SDGR_LINEAR;
desc.mipmaps     = 1;
unsigned tex = sdgr_upload_texture_ex(img.w, img.h, img.pixels, &desc);
```

Правила sRGB: **base color** и **emissive** грузятся как sRGB, карты
normal/metallic-roughness/occlusion — как линейные данные. Это соответствует
спецификации glTF и не даёт «выцветать» текстурам.

## 5. Редактор сцен

### 5.1 Сборка и запуск

```bash
python build.py editor
build/windows/release/sdge_editor.exe Subjects/character.glb
```

Ключи командной строки:

```
sdge_editor [model.glb|model.gltf] [--out file.gltf] [--tex image.png] [--selftest]
```

* `--out` — куда сохранять результат (по умолчанию `out/scene_edited.gltf`);
* `--tex` — картинка, которую надо положить на выбранный узел;
* `--selftest` — прогон открытия/правки/экспорта без интерфейса (для CI).

### 5.2 Управление

| Действие | Как |
|---|---|
| Выбрать узел | левая кнопка мыши по модели (инструмент «Select») |
| Выбрать узел в дереве | клик по строке в левой панели |
| Двигать | инструмент «Move», затем тянуть мышь |
| Вращать | инструмент «Rotate», тянуть влево/вправо |
| Масштабировать | инструмент «Scale», тянуть влево/вправо |
| Ограничить ось | кнопки X / Y / Z или клавиши `X`, `Y`, `Z` (ESC — снова свободно) |
| Сменить инструмент | клавиши `1` `2` `3` `4` или кнопки справа |
| Вращать камеру | правая кнопка мыши в окне модели |
| Приблизить | колесо мыши |
| Вписать модель в кадр | клавиша `F` или кнопка «Frame» |
| Наложить текстуру | вписать путь к картинке → «Apply» |
| Сохранить | кнопка «Save» (пишется `.gltf` + `.bin`) |

Узлы модели — это **узлы glTF-файла**. Дерево слева показывает всю иерархию,
у выбранного узла подсвечивается рамка, а в панели справа — его позиция,
угол и масштаб.

### 5.3 API редактора

```c
#include <sdge.h>

sdge_editor *ed = sdge_editor_create();
sdge_editor_open(ed, "Subjects/character.glb");

/* дерево */
int  count = sdge_editor_item_count(ed);
int  node  = sdge_editor_item_node(ed, 0);
const char *name = sdge_editor_item_name(ed, 0);

/* выбор */
sdge_editor_select(ed, 0);
int node = sdge_editor_selected_node(ed);

/* трансформация выбранного узла */
sdg_vec3 t, s; sdg_quat r;
sdge_editor_get_transform(ed, t, r, s);
t[1] += 0.5f;
sdge_editor_set_transform(ed, t, r, s);

/* текстура на узел (файл читается через stb_image) */
sdge_editor_apply_texture(ed, 0, "assets/textures/Body_baseColor.png",
                          SDGE_EDIT_TEX_BASE);
sdge_editor_clear_texture(ed, 0, SDGE_EDIT_TEX_BASE);

/* сохранение */
sdge_editor_export(ed, "out/edited.gltf");

sdge_editor_destroy(ed);
```

Текстовые слоты редактора совпадают со слотами рендерера:
`SDGE_EDIT_TEX_BASE`, `..._METALLIC`, `..._NORMAL`, `..._OCCLUSION`,
`..._EMISSIVE`.

### 5.4 Как это устроено внутри

* `sdge_editor` хранит один `sdge_model` и список плоских строк иерархии.
* Правка трансформации пишется прямо в `sdge_gltf_node` (TRS + матрица),
  после чего `sdge_model_refresh()` пересчитывает мировые матрицы.
* Выбор узла мышью — точное попадание по треугольникам: луч из камеры
  переводится в локальные координаты узла и проверяется тест Мёллера — Трамбора.
* Гизмо рисуется линиями (`sdgr_draw_lines_always`), рамка выделения —
  `sdgr_draw_box_wire`.
* Перетаскивание считается в плоскости взгляда камеры (для «Move») или как
  угол вокруг оси камеры / выбранной мировой оси (для «Rotate»). Дельта
  переводится в систему координат родителя, поэтому узел двигается правильно
  даже внутри вложенной иерархии.
* Текстура грузится через `sdga_image_load_rgba` (stb_image) и кладётся в
  **узел**, а не в материал: в движке появились
  `sdge_model_set_node_texture(model, node, slot, texture)` и
  `sdge_model_get_node_texture(...)`.

### 5.5 Экспорт

`sdge_editor_export()` пишет новый glTF 2.0:

* `<имя>.gltf` — JSON;
* `<имя>.gltf.bin` — данные мешей (POSITION/NORMAL/TEXCOORD_0 — float32,
  индексы — uint32, поэтому файл читается любым glTF- loader'ом);
* картинки встраиваются как **data URI** (base64), поэтому результат
  всегда самодостаточен;
* иерархия, имена, TRS, материалы и привязка текстур сохраняются;
* узел со своей текстурой получает **копию меша и копию материала** —
  текстура принадлежит только этому узлу.

Анимации и скины в экспорте пока не пишутся (в модели остаются исходными) —
это пункт в «что дальше».

## 6. Физика: что было исправлено

Физика 2D и 3D переписана: найденные ошибки приводили к тому, что тела
«закручивались», разлетались и тонули.

### 6.1 Исправленные ошибки

| Ошибка | Последствие | Исправление |
|---|---|---|
| Матрица ориентации использовалась транспонированной (строки вместо столбцов) | коробка сталкивалась «зеркально»: наклонённая коробка вела себя как наклонённая в другую сторону | `basis_axis()` возвращает **столбец** матрицы, локальные координаты считаются как `Rᵀ·v` |
| Эффективная масса считалась как `d·(I⁻¹(r×d))` вместо `(r×d)·(I⁻¹(r×d))` | импульс трения в углу коробки считался почти бесплатным, импульсы росли без ограничения и тело **улетало** | формула эффективной массы исправлена |
| Момент инерции был одним скаляром | длинная коробка вращалась как юла | полный диагональный тензор инерции (`Ixx = m/3·(hy²+hz²)` и т.д.), в мировых осях `R·I·Rᵀ` |
| Углы Эйлера интегрировались напрямую (`angle += angvel·dt`) | при вращении двух осей тело «закручивало» вокруг несуществующей оси | ориентация хранится **кватернионом**, интегрируется как `q' = q + ½·dt·(ω⊗q)`, эйлеры — только для чтения |
| Трение считалось по одной касательной | тело соскальзывало вбок и начинало вращаться вокруг свободной оси | решаются **обе** касательные, импульс ограничен кругом трения |
| Контакт был всегда одной точкой (центр перекрытия) | коробка на грани опрокидывалась, стопка разваливалась | полноценный **манифест** контакта: до 4 точек (3D) / 2 точек (2D) из обрезанного инцидентного граня |
| Указатели на тела лежали в перевыделяемом массиве | `sdph3_add_box()` возвращал указатель, который становился битым после добавления следующего тела | тела выделяются по одному, указатели **стабильны** |
| Кэш broadphase хранил «количество» вместо «ёмкости» | при удалении тел читалась память за пределами массива | отдельно `count` и `cap` |
| Гравитация по умолчанию была `(0,0,-9.81)` | в 3D (Y-up) тела падали по Z | гравитация по умолчанию `(0,-9.81,0)` |
| Демпфирование зависело от частоты кадров и съедало 70 % скорости в секунду | объекты «замирали» и не доезжали | формула `1/(1+damping·dt)`, значения по умолчанию 0.05 / 0.1 |
| Ограничение угловой скорости делалось внутри итераций | импульс терял вращательную часть, тело «перелетало» | ограничение только в конце шага |

### 6.2 Как пользоваться

```c
sdph3_world *w = sdph3_world_create();
sdph3_world_set_gravity(w, 0.0f, -9.81f, 0.0f);
sdph3_world_set_bounds(w, 1, -20, 0, -20, 20, 10, 20);
sdph3_world_set_iterations(w, 12);

/* статический пол (mass <= 0) */
sdph3_add_box(w, 0, -1, 0, 20, 1, 20, 0.0f);

/* динамическая коробка */
sdph3_body *b = sdph3_add_box(w, 0, 5, 0, 0.5f, 0.5f, 0.5f, 1.0f);

sdph3_set_angle(b, 0.4f, 0.0f, 0.0f);       /* наклон */
sdph3_set_velocity(b, 3.0f, 0.0f, 0.0f);    /* толчок  */

for (int i = 0; i < 120; ++i) sdph3_step(w, 1.0f / 60.0f);

printf("y = %.3f, spin = %.3f\n", b->pos[1], b->angvel[2]);
sdph3_world_destroy(w);
```

Новые возможности:

* типы тел: `SDPH3_STATIC`, `SDPH3_DYNAMIC`, `SDPH3_KINEMATIC`
  (`sdph3_set_type`) — кинематическое тело двигает всё, что касается его;
* `sdph3_set_position`, `sdph3_set_angle`, `sdph3_set_quat`,
  `sdph3_set_angular_velocity`, `sdph3_wake`, `sdph3_sleep`;
* `sdph3_set_restitution`, `sdph3_set_friction`;
* `sdph3_world_set_damping`, `sdph3_world_set_iterations`.

2D-мир (`physics2d.h`) получил те же изменения: стабильные указатели,
накопление импульсов, манифест из двух точек, корректный кэш broadphase.

### 6.3 Проверка

Физика не зависит от окна, её можно тестировать без графики:

```bash
python build.py test
```

Тест (`tests/physics_test.c`) прогоняет несколько симуляций и проверяет
результат (1–20 секунд симуляции, 60 fps):

* наклонённая коробка падает плашмя и засыпает, угловая скорость → 0;
* стопка из четырёх коробок не тонет и не разъезжается;
* шар катится: линейная и угловая скорости связаны (`v = ω·r`);
* указатели на тела остаются валидными после добавления и удаления;
* спящее тело просыпается, когда на него падает другое.

## 7. Мелочи, о которых стоит знать

* **Координаты**: правая система, Y — вверх, -Z — вперёд (как в glTF).
  Матрицы `sdg_mat4` — column-major (совпадает с загрузкой в GL без transpose).
* **Отсечение**: `sdgr_set_camera()` считает фрустум, `sdge_model_draw()`
  отсекает примитивы по bounding sphere.
* **Прозрачность**: материалы с `alphaMode = BLEND` сортируются от дальних к
  ближним и рисуются после непрозрачных, глубина при этом не пишется.
* **Скининг**: скины используют палитру суставов анимационного плеера;
  статические модели считают мировые матрицы один раз при загрузке.
* **Шрифты**: `assets/font.h` умеет TTF/OTF; в GUI используется общий атлас.
